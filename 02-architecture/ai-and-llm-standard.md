# Enterprise AI and LLM Integration Standard

## Purpose

When integrating Large Language Models (LLMs) or GenAI services into enterprise products (ERP, workflow, automation, customer-facing SaaS), AI capabilities must be treated with the same rigor as any external, non-deterministic third-party dependency.

An LLM is a probabilistic system: **it cannot be trusted as an authoritative security boundary, access controller, or database query generator.**

---

## 1. Security and Threat Mitigations

### A. Prompt Injection Defense (Direct & Indirect)

1. **MUST NOT** concatenate untrusted user input directly into system instructions without structural boundaries (e.g., use official SDK parameter roles like `system`, `user`, `assistant`).
2. **MUST** treat data retrieved from external sources (web pages, emails, user attachments, customer tickets) as untrusted input. Indirect prompt injection can hijack model execution.
3. **MUST NOT** grant an LLM tool access to perform destructive or high-risk actions (e.g., delete tenant, refund payment, assign administrative role) without **explicit human-in-the-loop confirmation**.

```text
Untrusted Input / External Data
         ↓
Sanitization & Parameterized Roles (system / user / context)
         ↓
LLM Execution (with constrained, low-privilege tools)
         ↓
Strict Output Validation (Schema + Business Rules)
         ↓
Human Confirmation (if action is irreversible/destructive)
```

### B. PII and Data Privacy

1. **MUST** sanitize, mask, or redact Personally Identifiable Information (PII), credentials, payment tokens, and secrets before sending payloads to third-party model providers.
2. **MUST** verify the model provider’s data-privacy agreement:
   - Zero Data Retention (ZDR) policy.
   - Confirmation that client data is **not** used to train public foundational models.
3. **MUST** log AI interactions without persisting raw sensitive prompt text or unredacted completions in general application logs.

---

## 2. Structured Outputs and Validation

1. **MUST** enforce structured outputs (JSON schema, tool calls, or typed response formats) for any programmatic processing. Free-form text parsing with regular expressions is prohibited for critical workflows.
2. **MUST** validate model outputs server-side using strict schemas (e.g., Zod, Jackson, Pydantic) before passing data to backend business logic or persistence layers.
3. **MUST NOT** execute code, SQL queries, or shell commands generated by an LLM directly against production databases or systems without an isolated, sandboxed execution environment with network egress restrictions.

---

## 3. Cost Control, Rate Limiting, and Telemetry

LLM calls can cause catastrophic cost spikes and denial-of-wallet attacks if unmetered.

1. **MUST** enforce server-side rate limits on all AI-powered endpoints (per user, per tenant, and per IP).
2. **MUST** set a strict timeout (e.g., 15–30 seconds) on all LLM requests; never allow indefinite hangs.
3. **MUST** cap maximum token usage: specify explicit `max_output_tokens` on every invocation.
4. **MUST** record token usage telemetry:
   - Prompt tokens, completion tokens, cached tokens, and estimated cost per tenant.
   - Tag metrics by feature name, model version, and tenant ID.
   - Alert operations when a tenant or feature burns through a defined quota.

---

## 4. Resilience and Fallback Design

1. **MUST** design for provider outages and latency degradation.
   - Implement graceful degradation: if the AI service fails or times out, the core workflow must either offer a manual fallback or return a clear, safe error.
   - Use pooled HTTP clients with exponential backoff and circuit breakers (as defined in `04-backend/spring-boot/http-client-standard.md`).
2. **SHOULD** use asynchronous background jobs (Outbox/Queue) for non-interactive or batch AI workflows (e.g., report summarization, batch document processing). Do not block user HTTP request threads for operations exceeding 3 seconds.
3. **SHOULD** implement semantic or exact-match caching for frequently asked, static queries to reduce cost and latency.

---

## 5. Auditability and Accountability

1. **MUST** record an audit event whenever an AI system generates content that influences business records, recommendations, approvals, or financial calculations.
2. **MUST** identify the actor as an automated AI system (e.g., `actor_type = "AI_MODEL"`, `model_name = "gemini-1.5-pro"`), including prompt template version and confidence score where applicable.
3. **MUST** provide users with clear visibility when content or decisions are AI-assisted or AI-generated.
